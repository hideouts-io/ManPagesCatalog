## Verified local scan-performance milestone

- [x] Repeatable native Swift stress-tree generation and ownership-checked cleanup. Acceptance: deterministic counts/content, resumable bounded generation, explicit file/storage/reserve limits, and refusal to delete unowned or foreign data. Verification: actual 2,000,000 ordinary files (1,800,000 empty; 200,000 with 64-byte nonmanual payloads), independently verified fixture manifests; graceful interruption, same-root expansion, wrong-token/foreign-file cleanup refusals, and malformed-checkpoint/no-shrink cases. This corpus exercises traversal metadata; it is not a large manual-content workload.
- [x] Production Deep Scan traversal at two-million-file scale. Acceptance: inspected counters and expected manual identities/locations agree; loops terminate and unsupported/inaccessible paths stay explicit. Verification: warm APFS scan inspected 2,000,021 regular entries in 2,091 directories; 18 locations grouped into 9 indexed manuals; zero pending paths. Discovery took 100.736 seconds, approximately 19,854 files/sec; pending queue peak 2,999. This verifies selected synthetic roots, not whole-Mac coverage.
- [x] Local monotonic discovery/indexing diagnostics with separate queues, cancellation, RSS and MainActor scheduling measurements. Acceptance: legacy coverage stays readable, companion reports define counts/phases/rates, resumed segments exclude prior counts, malformed reports fail clearly. Verification: real-manual integration, actual app-scan export, serial enabled/disabled ABBA and reverse BAAB runs, and persisted-report validation. All observations are retained; final batch differences of +32.87% and −4.67% do not isolate causal telemetry cost. CLI scheduling is not rendered-app response time.
- [x] Remove demonstrated per-file temporary-object retention. Acceptance: exact discovery parity survives the memory fix. Verification: full two-million-file production run; sampled resident peak 27,115,520 bytes and kernel maximum RSS 28,573,696 bytes. This CLI measurement does not bound app memory or one enormous directory.
- [x] Durable cancellation and resume at measured scale. Acceptance: stopped worker, checkpoint and retained inventory reopen; resumed identities, locations, aliases, languages and versions match a fresh scan. Verification: five-second cancellation retained 89,233 inspected entries and 18 locations, with 16.632 ms preservation latency; resume completed 1,910,788 remaining entries in 99.074 seconds with exact parity and no pending paths.
- [x] Selected additional local-volume correctness and reference-license inspection. Acceptance: roots and aliases avoid repeated traversal; reuse requirements are checked before copying code. Verification: controlled 512 MiB APFS image, 2 manuals, 3 inspected files and 5 directories; image ejected with provenance retained. MacDirStat AGPL/MIT/unlicensed sources were inspected as design evidence; no source was copied. The image shares host physical storage and is not an external-drive performance test.
- [x] Reduce demonstrated main-window work during progress updates. Acceptance: encode retained inventories off MainActor and rebuild source filters only when inventory/coverage changes, preserving search and reader state. Verification: 20 real integration tests; isolated packaged-app scan with a copied 14,095-manual library; search/read/Find and cancellation/relaunch/resume retained 60,618 prior locations and completed all 2,000,021 inspected files. Final comparable busy probes observed 1.00–1.58 seconds including automation overhead, versus 2.09–4.78 seconds in the baseline; worst sampled MainActor delay was 18.14 ms. These observations do not establish sub-500-ms event-to-render latency.

- [x] Stream very wide directory enumeration and bound pending work. Acceptance: exact counts/locations on a separate 2,000,000-sibling tree, CLI maximum RSS below 128 MiB, durable cancellation within 250 ms and no greater than 10% broad/deep regression on the measured host. Verification: final production scan inspected 2,000,021 files in 114.432 seconds at 15.38 MiB kernel maximum RSS; 18 locations grouped into 9 indexed manuals; peak pending work 73 unfinished folders/entries. CLI cancellation preserved 89,452 files in 1.889 ms; cancellation during prefix replay retained identical counters, and resume completed the remaining 1,910,569 files with exact parity. The broad/deep pair took 101.820 seconds versus 110.807 seconds baseline. The final 26-test suite verified unchanged and metadata-only resume, changed-entry and replaced-path rejection, and retained inventory/search with an incompatible checkpoint. An extracted-app copy resumed its existing 1,338,406-file checkpoint to 2,000,000 files, retained nine manuals, displayed measured coverage and saved a readable PDF plus matching coverage/telemetry; a separate absent-library launch discovered and read the fixtures. A 130-level tree reported its unsupported subtree at the 128-stream limit explicitly. Cache state and host background activity were uncontrolled; these are observed selected-root results, not whole-machine or universal speed guarantees.

- [ ] Cloud-placeholder exclusion and explicit network-folder opt-in. Acceptance: an offline cloud placeholder is not hydrated and an unselected mounted network share is not read; explicit selection includes only its authorized subtree. Verification: controlled real File Provider and mounted-share cases without changing security settings. Metadata guards are implemented; live provider/network behavior is unverified.
- [ ] macOS 13+ and Intel deployment support. Acceptance: extracted application discovers, reads and exports on the oldest supported OS and Intel hardware without checkout/tools installed by a developer. Verification: clean-machine matrix; universal compilation alone is insufficient.
- [ ] Isolate diagnostic sampling cost under comparable cache conditions. Acceptance: predefined warmup, both telemetry orders, all observations retained, per-sampling CPU/wall time and bounded sample storage, with an explicit estimate or stated unresolved confounding. Current sampling is bounded to a one-second target and 3,600 retained samples, but final eight-run enabled mean was 13.37% higher with conflicting batch estimates; a negligible-overhead claim is unsupported.

- [ ] Stream guards and durable writes under untested filesystem conditions. Acceptance: preserve the last valid cursor/inventory across slow or failed atomic writes and abrupt termination; explicitly report union-mount and non-UTF-8 entry gaps without hydration or network traversal. Verification: isolated local-volume/write-pressure and entry-name cases, same-boot relaunch, exported diagnostics. Bounded replay, changed-directory rejection and version-1 checkpoint retention are verified; interruption during an active atomic write, union mounts and non-UTF-8 entries are implemented but unverified.

## P0 — next coherent milestone: bound manual-rich indexing and publication

Dependencies: verified local stress and telemetry foundation above. Retain the native reader, PDF export and current coverage classifications.

- [ ] Bound manual-rich indexing, partial snapshots and search publication. Outcome: large manual inventories stay usable during indexing and checkpoint updates. Acceptance: at least 10,000 distinct validated manuals, observable indexing queue, independently measured search/read/Find responses under 500 ms and durable pause/resume parity with explicit low-disk/write errors. Verification: isolated mixed installed/synthetic corpus, production formatter/FTS, stable-ID rendered interactions, RSS and checkpoint size/time measurements. Nine indexed groups establish correctness, not indexing capacity. Inventory serialization now runs off MainActor and source filters are cached. The final copied-library GUI run still observed 598.70 MB sampled RSS, 1.491 s durable pause, and up to 1.877 s action-to-AX observation including automation overhead; remaining inventory publication/search costs need independent measurement and bounds.
- [ ] Complete a resumable whole-filesystem measurement. Outcome: measured coverage for all accessible local mounted volumes. Acceptance: no pending paths, all skipped paths classified, duplicates explained, filesystem changes between start/resume clearly scoped. Verification: real long scan, pause/relaunch/resume, exported report; preserve the current session checkpoint until measured.
- [ ] Reconcile directory aliases without redundant traversal. Outcome: retain alternate directory-symlink paths for discovered manuals while visiting physical directories once. Acceptance: every encountered alias location is represented or explicitly linked to its canonical coverage record; cycles terminate. Verification: real man-root symlinks and an isolated cyclic tree. Current directory aliases are recorded as exclusions; file aliases are preserved.
- [ ] Strengthen recovery across filesystem change, remount and reboot. Outcome: resume safely or restart only affected work. Acceptance: compare opened-directory identities and canonical /Users/Data-volume aliases; changed volume identity and directory contents cannot be mistaken for previously covered data; interrupted indexing resumes from durable metadata. Verification: controlled mounted-volume/reboot tests. Current checkpoints deliberately require the same boot and a stable clock; fresh scans reconcile already visited folders.

## P1 — broaden verified input support

Depends on P0 coverage data to prioritize observed gaps.

- [ ] Safe embedded `.so` includes. Outcome: read/index/export the installed zshall aggregate (14 includes) with per-include provenance. Acceptance: validate permissions, network consent, materialization, cycles, depth and expanded size for every target; include changes invalidate fingerprints; `.mso` and conditional/macro-generated includes are never silently misinterpreted. Verification: real zshall plus bounded include-chain/cycle cases. Whole-file aliases already work; embedded includes currently report unsupported.
- [ ] Additional compression using the smallest supported runtime. Outcome: decode XZ/LZMA/Zstandard/LZ4/lzip where a reliable native/system or bundled dependency is justified. Acceptance: validate container contents, cancellation and decompression limits; include licenses/resources and test extracted packaging. Verification: real compressed manuals, renamed containers, corrupt input and oversized expansion. Current signatures identify unsupported containers but do not decode them; archives are not traversed. Evaluate available SDK/system APIs before adding a dependency.
- [ ] Preformatted cat pages and unusual headers. Outcome: display validated preformatted manuals with an explicit format label and usable metadata. Acceptance: distinguish formatted text from arbitrary numbered files, handle overstrike/ANSI safely, preserve native reading and PDF export semantics, and identify uncertain names/languages. Verification: installed cat-page corpus or pages generated from real installed manuals. Headerless nonstandard filenames and headers after the initial 64 KiB currently remain discovery gaps.
- [ ] Formatter compatibility and actionable diagnostics. Outcome: resolve observed sudoers/table/macro failures and make formatting issues reachable from the selected manual. Acceptance: readable HTML, searchable text and export agree, or each operation explains its own limitation without silently substituting incomplete output. Verification: affected installed sources and source-to-rendered comparison.

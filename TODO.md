## Verified local scan-performance milestone

- [x] Repeatable native Swift stress-tree generation and ownership-checked cleanup. Acceptance: deterministic counts/content, resumable bounded generation, explicit file/storage/reserve limits, and refusal to delete unowned or foreign data. - [x] Production Deep Scan traversal at two-million-file scale. Acceptance: inspected counters and expected manual identities/locations agree; loops terminate and unsupported/inaccessible paths stay explicit. Verification: warm APFS scan inspected 2,000,021 regular entries in 2,091 directories; 18 locations grouped into 9 indexed manuals; zero pending paths. Discovery took 100.736 seconds, approximately 19,854 files/sec; pending queue peak 2,999. This verifies selected synthetic roots, not whole-Mac coverage.
- [x] Local monotonic discovery/indexing diagnostics with separate queues, cancellation, RSS and MainActor scheduling measurements. Acceptance: legacy coverage stays readable, companion reports define counts/phases/rates, resumed segments exclude prior counts, malformed reports fail clearly. Verification: real-manual integration, actual app-scan export, serial enabled/disabled ABBA and reverse BAAB runs, and persisted-report validation. All observations are retained; final batch differences of +32.87% and −4.67% do not isolate causal telemetry cost. CLI scheduling is not rendered-app response time.
- [x] Remove demonstrated per-file temporary-object retention. Acceptance: exact discovery parity survives the memory fix. Verification: full two-million-file production run; sampled resident peak 27,115,520 bytes and kernel maximum RSS 28,573,696 bytes. This CLI measurement does not bound app memory or one enormous directory.
- [x] Durable cancellation and resume at measured scale. Acceptance: stopped worker, checkpoint and retained inventory reopen; resumed identities, locations, aliases, languages and versions match a fresh scan. Verification: five-second cancellation retained 89,233 inspected entries and 18 locations, with 16.632 ms preservation latency; resume completed 1,910,788 remaining entries in 99.074 seconds with exact parity and no pending paths.
- [x] Selected additional local-volume correctness and reference-license inspection. Acceptance: roots and aliases avoid repeated traversal; reuse requirements are checked before copying code. Verification: controlled 512 MiB APFS image, 2 manuals, 3 inspected files and 5 directories; image ejected with provenance retained. MacDirStat AGPL/MIT/unlicensed sources were inspected as design evidence; no source was copied. The image shares host physical storage and is not an external-drive performance test.
- [x] Reduce demonstrated main-window work during progress updates. Acceptance: encode retained inventories off MainActor and rebuild source filters only when inventory/coverage changes, preserving search and reader state. Verification: 20 real integration tests; isolated packaged-app scan with a copied 14,095-manual library; search/read/Find and cancellation/relaunch/resume retained 60,618 prior locations and completed all 2,000,021 inspected files. Final comparable busy probes observed 1.00–1.58 seconds including automation overhead, versus 2.09–4.78 seconds in the baseline; worst sampled MainActor delay was 18.14 ms. These observations do not establish sub-500-ms event-to-render latency.

- [x] Stream very wide directory enumeration and bound pending work. Acceptance: exact counts/locations on a separate 2,000,000-sibling tree, CLI maximum RSS below 128 MiB, durable cancellation within 250 ms and no greater than 10% broad/deep regression on the measured host. A 130-level tree reported its unsupported subtree at the 128-stream limit explicitly. Cache state and host background activity were uncontrolled; these are observed selected-root results, not whole-machine or universal speed guarantees.

- [x] Bound manual-rich formatter, index and metadata publication work. ## Implemented, validation still incomplete

- [ ] Paired coverage replacement after a later write fails. Outcome: preserve or explicitly report each destination state after partial replacement. Acceptance: restore previous bytes/absence when possible and retain the original failure plus any restoration failures. Verification: isolated second-write denial/storage-pressure and interrupted replacement cases. Both reports are prepared before writing, each write is atomic, and rollback is implemented; preflight conflicts, oversize prior files and first-write denial are verified. Second-write rollback, restoration failure, concurrent destination modification and process termination between the two writes are unverified; the pair is not a crash-atomic transaction.

- [ ] Whole-local-volume traversal, per-location coverage and resumable checkpoints at machine scale. Acceptance: complete a real Deep Scan, account for every queued location and explain all inaccessible/excluded/failed/unsupported paths; no complete-machine claim based only on traversal completion. - [ ] macOS 13+ and Intel deployment support. Acceptance: extracted application discovers, reads and exports on the oldest supported OS and Intel hardware without checkout/tools installed by a developer. Verification: clean-machine matrix; universal compilation alone is insufficient.
- [ ] Isolate diagnostic sampling cost under comparable cache conditions. - [ ] Stream guards and durable writes under untested filesystem conditions. ## P1 — broaden verified input support

Depends on P0 coverage data to prioritize observed gaps.

- [ ] Safe embedded `.so` includes. Outcome: read/index/export the installed zshall aggregate (14 includes) with per-include provenance. Acceptance: validate permissions, network consent, materialization, cycles, depth and expanded size for every target; include changes invalidate fingerprints; `.mso` and conditional/macro-generated includes are never silently misinterpreted. Verification: real zshall plus bounded include-chain/cycle cases. Whole-file aliases already work; embedded includes currently report unsupported.
- [ ] Additional compression using the smallest supported runtime. Outcome: decode XZ/LZMA/Zstandard/LZ4/lzip where a reliable native/system or bundled dependency is justified. Acceptance: validate container contents, cancellation and decompression limits; include licenses/resources and test extracted packaging. Verification: real compressed manuals, renamed containers, corrupt input and oversized expansion. Current signatures identify unsupported containers but do not decode them; archives are not traversed. Evaluate available SDK/system APIs before adding a dependency.
- [ ] Preformatted cat pages and unusual headers. Outcome: display validated preformatted manuals with an explicit format label and usable metadata. Acceptance: distinguish formatted text from arbitrary numbered files, handle overstrike/ANSI safely, preserve native reading and PDF export semantics, and identify uncertain names/languages. Verification: installed cat-page corpus or pages generated from real installed manuals. Headerless nonstandard filenames and headers after the initial 64 KiB currently remain discovery gaps.
- [ ] Formatter compatibility and actionable diagnostics. Outcome: resolve observed sudoers/table/macro failures and make formatting issues reachable from the selected manual. Acceptance: readable HTML, searchable text and export agree, or each operation explains its own limitation without silently substituting incomplete output. Verification: affected installed sources and source-to-rendered comparison.
